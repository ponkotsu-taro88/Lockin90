# Lock-in 90 — 変更仕様 2026-10-07

デザインツール側で実装する変更の指示書。`source/Lock-in App.dc.html` の `Component` クラスが対象。
実装後、書き出した `index.html` をリポジトリ直下に置き、`node scripts/inject-head.mjs index.html` を実行する（CLAUDE.md 参照）。

実装順は **0 → 1 → 2 → 3 → 4**。0 を飛ばさないこと。

---

## ⚠️ 先に読むこと — 既存コードの2つの地雷

### 地雷1: `v` を上げると全履歴が消える

`Component.load()`（現 638行目）:

```js
static load() {
  try { const d = JSON.parse(localStorage.getItem(Component.KEY)); if (d && d.v === 1) return d; } catch (e) {}
  return Component.freshDb();
}
```

`d.v === 1` 以外は **無言で `freshDb()` に差し替わる**。`v: 1` を `v: 2` にした瞬間、ユーザーの端末の全記録が消える。

**→ 本仕様の追加フィールドはすべて任意（optional）。`v` は 1 のまま変更しない。**
読み出し側で「未定義なら既定値」として扱うこと。マイグレーション処理は書かない。

### 地雷2: セット編集が新フィールドを消す

`eSave`（現 1046行目）:

```js
y.ex[st.edit.i].sets[st.edit.j] = { w: st.edit.w, r: st.edit.r };
```

セットオブジェクトを**丸ごと置換**している。このままだと、EDIT を押した瞬間に `t`（種別）や `d`（ドロップ）が消える。

**→ 既存を展開して上書きすること:**

```js
const s0 = y.ex[st.edit.i].sets[st.edit.j];
y.ex[st.edit.i].sets[st.edit.j] = { ...s0, w: st.edit.w, r: st.edit.r };
```

## 0. JSON エクスポート / インポート（最優先）

以降の 2・3・4 はデータ構造に手を入れる。現状バックアップ手段が一切なく、失敗すると復旧できないため、**これを先に入れて動作確認する**。

### 配置
Settings 画面、「全データリセット」の**上**に新しいセクション `BACKUP`。

### エクスポート
- ボタン `EXPORT`
- `JSON.stringify(db)` を生成
- **iOS のホーム画面アプリ（standalone）ではファイルダウンロードが不安定**。以下の2経路を両方用意する:
  1. `navigator.clipboard.writeText()` でクリップボードへコピー（成功時「コピーしました」と表示）
  2. 同じ内容を全選択可能な `<textarea readonly>` にも表示（クリップボードが使えない環境の保険）
- 出力はラップしたオブジェクトにする:
  ```json
  { "app": "lockin90", "v": 1, "exportedAt": "2026-10-07T12:34:56.789Z", "db": { ... } }
  ```

### インポート
- ボタン `IMPORT` → `<textarea>` に貼り付け
- 取り込み前に**必ず検証**し、1つでも満たさなければ中止してエラー文言を出す:
  - JSON としてパースできる
  - `app === 'lockin90'` かつ `v === 1`
  - `db.sessions` / `db.lib` / `db.menus` が配列、`db.plan` / `db.walks` がオブジェクト
- 検証通過後、**2回タップ確認**（既存の削除操作と同じ作法）を経て `db` を差し替え
- 差し替え時は `activeId` を `null` にする（他端末の進行中セッションを引き継がない）

## 1. パレットを vivid 化

`Component.P`（現 605–607行目）を差し替えるだけ。**保存データは色の添字**（`colors: [0,2,6,1,3,4,8]`）なので、履歴には一切影響しない。

```js
static P = [['Pink',0],['Lilac',320],['Lavender',290],['Periwinkle',265],['Sky',230],['Aqua',195],['Mint',160],['Lime',130],['Lemon',100]]
  .map(([name, h]) => ({ name, color: `oklch(0.75 0.125 ${h})` }))
  .concat([{ name: 'Stone', color: 'oklch(0.75 0.012 90)' }]);
```

### 背景
現行の `oklch(0.85 0.1 H)` は **9色中4色が sRGB 色域外**で、ブラウザに圧縮されていた（Periwinkle 上限 0.074 / Lavender 0.080 / Pink 0.089 / Sky 0.093 に対し指定 0.1）。紫・ピンク系だけが濁って見えていた原因。

L=0.85 では全色を揃えると 0.074 までしか上げられないため、**L を 0.75 に下げて C=0.125** とした。この値は9色すべてが sRGB 内に収まる上限。黒文字（`#1E1F1C`）とのコントラストは最悪 7.03:1 で WCAG AA 合格。

### 変更しないもの
- アクセント `#FF6B1A` とボタン色はそのまま（日替わり色にはしない）
- 90日マスの「今日」`#FF6B1A`、カレンダーの今日リングもオレンジのまま

## 2. アシスト種目の表記（表記のみ・体重は扱わない）

アシスト付き懸垂は**重りが増えるほど楽**なので、現状の `45kg × 10` 表示は「成長」に見えて実態と逆になっている。

### データ
`lib[]` に任意フィールドを1つ追加。未定義は `false` 扱い。

```
lib[]: + assist?: boolean
```

既定で `assist: true` にする種目: `Chin-up / Assisted Chin-up`

### 表示
`assist` が真の種目は、重量を出すすべての箇所で接頭辞を付ける:

- セット一覧 … `アシスト 45kg × 10`
- LOG SET ボタンの副題 … `アシスト 45kg × 10`
- WEIGHT 入力欄のラベル … `WEIGHT` → `ASSIST`
- 前回記録 / History / Summary … 同様に `アシスト` を付ける

### 比較方向の反転（重要）
`assist` が真の種目では **数値が小さいほど改善**。前回比を出しているすべての箇所で符号を反転する:

- Logging 画面の前回比（現 985行目 `logSets` の `d = t.r - pr`）
- Summary の「種目ごとの前回比」

reps の比較は従来通り（多いほど良い）。反転するのは**重量の比較のみ**。

### 種目ライブラリ編集画面
`assist` のオン/オフを切り替えるトグルを追加（名前・部位・レップ範囲・重量刻み・休憩の並びに追加）。

## 3. セット種別（ウォームアップ / ネガティブ / ドロップ）

### データ

```
sets[]: + t?: 'warm' | 'neg' | 'drop'    // 未定義 = 通常セット
        + d?: [{ w, r }, ...]            // t==='drop' のときのみ。2段目以降の重量
```

既存の `{w, r}` は「`t` 未定義の通常セット」としてそのまま有効。

### UI — 種別タブ
WEIGHT/REPS 入力の**上**に4つのタブを横並びで置く:

```
[ WARM-UP ]  [ NORMAL ]  [ NEGATIVE ]  [ DROP ]
```

- 既定の選択は `NORMAL`
- 選択状態は既存のタブUI（`#1E1F1C` 背景 + `#ECEDE6` 文字）に合わせる
- セットを1つ記録するごとに `NORMAL` に戻す

### ウォームアップ / ネガティブ — タグのみ
`logSet` で `t` を付けて push するだけ。

```js
e.sets.push({ w: s.w, r: s.r, ...(s.setType ? { t: s.setType } : {}) });
```

セット一覧では行頭に小さいラベルを出す（`W` / `NEG` / `DROP`、`#5F6059`）。

### ドロップセット — フロー変更が必要
1セットの中に複数の重量が入るため、タブだけでは足りない。

1. `DROP` を選択すると、LOG SET ボタンの表記が **`LOG & DROP`** に変わる
2. 押すと1段目が `{w, r, t:'drop', d:[]}` として push され、**セットは開いたまま**
3. 重量を下げて再度押すと、`d` に `{w, r}` が追記される
4. ボタンの隣に出る **`セット確定`** を押すとセットが閉じる

**休憩タイマーの開始タイミングに注意**: 現 `logSet` は押すたびに `restEnd` を更新している。ドロップ中は**タイマーを開始しない**。`セット確定` を押したときのみ開始する。

表示: `45kg × 10 → 30 × 8 → 20 × 6`
Total reps はドロップ内の全 reps を合算する（10+8+6 = 24）。

### ウォームアップは記録比較から除外（重要）

現在の前回比は**配列の添字で突き合わせている**:

- `prefill`（現 664–670行目）… `p.sets[n]`
- `logSets`（現 985行目）… `p.sets[j]`

ウォームアップを同じ配列に混ぜると、前回2本・今回1本のときに添字がずれて**比較が1セット分だけ狂う**。

**→ 比較・前回記録・Total reps はすべて `t !== 'warm'` で絞ったリストに対して行う。**

```js
const work = sets.filter(s => s.t !== 'warm');
```

セット番号の表示（S1, S2…）も work 側で採番し、ウォームアップは `W1` のように別採番にする。

## 4. 片側プレート / ダンベルの表記

### データ

```
lib[]: + pair?: 'plate' | 'dumbbell'    // 未定義 = 通常
```

### 保存する値
**ユーザーが打った数字をそのまま `w` に保存する**（片側の重量 / ダンベル1個の重量）。合計は表示時に計算する。バー・マシン本体の重量は**加算しない**。

### 表示

| `pair` | 入力 | 表示 |
|---|---|---|
| 未定義 | 60 | `60kg` |
| `plate` | 15 | `片側 15kg ／ 計 30kg` |
| `dumbbell` | 20 | `20kg × 2 ／ 計 40kg` |

狭い場所（LOG SET ボタンの副題など）は `15kg×2 (30)` の短縮形でよい。

`±` の刻みは**打つ数字（片側）に対して**効く。15kg刻みなら片側に1枚追加＝合計+30kg という挙動で正しい。

### 種目ライブラリ編集画面
`通常 / 片側プレート / ダンベル` の3択セレクタを追加。対象種目をユーザー自身が設定できるようにする（ジムによって構成が違うため、コード側に種目リストを固定しない）。

既定値はすべて「通常」。初期ライブラリに対して自動で `plate` を立てることはしない。

### ⚠️ 既存記録への影響
これまで合計値を打っていた種目に `plate` を立てると、過去の記録が倍の値で表示される。実装後、ユーザーに「対象種目を設定したら、その種目の過去記録を確認してください」と伝えること。

## データ構造の差分まとめ

`localStorage` キー `lockin90.v1` は変更しない。`v` は 1 のまま。追加はすべて任意フィールド。

```
lib[]:  { id, name, cat, step, lo, hi, rest }
      + { assist?: boolean, pair?: 'plate'|'dumbbell' }

sets[]: { w, r }
      + { t?: 'warm'|'neg'|'drop', d?: [{w, r}] }
```

既存データはすべてそのまま読める（新フィールドが未定義＝従来の挙動）。
